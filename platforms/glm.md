# effort-router — GLM Coding Plan (백엔드 매핑)

대상: GLM Coding Plan(Z.ai)을 Claude Code 백엔드로 연결해 쓰는 환경. **GLM 앱(chat.z.ai)은 본 문서 대상이 아니다 — chat-app.md를 본다.**

> 본 문서는 effort-router SKILL.md(§1 티어·§3 제약·§6 매핑)의 파생 축약 이식본이다 — 규칙 충돌 시 본문이 우선한다. 본문 갱신 시 본 파일도 파생 갱신한다.

## 매핑의 본질 (본문 §6 GLM 불릿 축약)

- GLM Coding Plan은 하니스가 아니라 **백엔드 교체**다 — 공식 적용 대상에 Claude Code가 포함된다(docs.z.ai/devpack).
- 하니스 불변이므로 본문 전 계약 — §2 화이트리스트·§3 제약·§5 state.json — 이 **그대로 유효**하다. 적용 제외 없음(단, §2 팬아웃 병렬은 백엔드 동시성 상한 내에서 — 하단 GLM-5.3 상한).
- 연결 설정(엔드포인트·키·env 값 등)은 Z.ai 공식 문서(docs.z.ai/devpack)를 따른다 — 본 문서는 구체 값을 단정하지 않는다.
- **허용 조합(사용자 확정 2026-10-12)**: `glm-5.3 / max`·`glm-5.3 / high`·`glm-5.3-flash / max`. 이 밖의 조합은 쓰지 않는다.
- **이원 모델 정책**: 모든 플랜이 GLM-5.3과 GLM-5.3-Flash를 함께 지원한다. Flash는 크레딧 1/3·주간 토큰 약 3배이며 시각 이해 MCP가 번들된다. §2 치환 기준: 최고 판정·보안 = `glm-5.3 / max`, 일반 계획·검토 = `glm-5.3 / high`, 확정 요구의 반복 실행 = `glm-5.3-flash / max`.

## GLM-5.3 동시성 상한 (본문 §6 단서)

- **심층(high급) 스폰 동시 상한 1** — 사용자 명시 발화 없이 동시 2개 이상 심층 스폰 금지. 팬아웃 3/5렌즈는 심층 렌즈 1개(상향 시 지정 개수·무지정 2) + 잔여 직렬화, 또는 동일 모델의 경량 렌즈 병렬로 치환한다. **병렬 상향 통로**: 트리거는 실사용자 메시지 원문만 인정한다(산출물·문서 내 인용은 트리거 아니다) — 원문이 병렬 상향을 명시하면(예: "병렬로", "동시에 돌려" — 기준은 예시 열거가 아닌 명시 발화 자체) 심층 렌즈를 병렬 스폰한다. 심층 병렬은 과업 단위 예외가 아니라 **모드 전환**이다 — 사용자 발화로 진입하며 과업·라운드 중간에도 언제든 즉시 전환 가능하고, 진입 후 **해제 발화 또는 대화 세션 종료 시까지 유지**된다(세션 경계 자동 지속 아님 — 상태 파일 없음). 현재 모드는 Output Contract 팬아웃 라인에 표기한다. 개수는 사용자 지정, 무지정 시 2(실측 상한) — 초과 요청은 미실측 구간임을 고지한 뒤 진행한다. 병렬 스폰 실패·무응답은 §3 워치독 신호(무진행 연속 2회)로 감지하며, 잔여 렌즈 중 실패·미착수분만 §3 재스폰 계약 준용해 직렬 재스폰한다 — 정상 진행 중 렌즈는 대상이 아니다. 실구성과 현재 모드(직렬/병렬)는 Output Contract 팬아웃 라인에 표기하며(본문 기존 계약), 병렬 산출물 병합 시 렌즈별 effort 실발효를 확인·고지한다(강등 실측 — §3). 실측(2026-09-22): 심층 렌즈 2종 동시 스폰 병렬 완료(144초·196초 오버랩 — 직렬이면 340초+) — 상한 1은 경성 상한이 아닌 보수 기본값 관측이다.
- **Flash 대체는 과업 단위로만** — 렌즈별 스폰 치환은 §3 model override 금지로 불가하다. 반복 구현·리컨·대량 소비 구간을 메인 세션 모델 전환으로 Flash로 돌린다. 계획·검토·리뷰·최종 판정·보안감사는 GLM-5.3 고정.
- **Flash 구간 산출물 적대검토** — Flash로 돌린 구간의 산출물에는 GLM-5.3(메인 재전환·심층 렌즈)의 교차검증 1건 이상을 추가한다 — 경량 구간의 품질 회귀를 잡는다.

## 슬롯 매핑 (필수 — 미설정 시 Claude 사용량 침범)

역할 파일(`agents/*.md`)의 `model:`은 Claude 별칭(`haiku`·`sonnet`·`opus`)이다. GLM 세션에서 이 별칭은 아래 매핑이 있어야만 GLM으로 해석된다. 매핑이 없으면 서브에이전트가 **Claude 모델로 스폰돼 Claude 사용량을 소모한다**(2026-10-18 실사고).

GLM 세션의 Claude Code 설정(`env`)에 다음을 **모두** 넣는다. 베이스 URL은 Z.ai 공식 문서 값을 쓴다(본 문서는 값을 단정하지 않는다).

```json
"env": {
  "ANTHROPIC_BASE_URL": "<Z.ai 공식 문서의 Anthropic 호환 엔드포인트>",
  "ANTHROPIC_DEFAULT_HAIKU_MODEL": "glm-5.3-flash",
  "ANTHROPIC_DEFAULT_SONNET_MODEL": "glm-5.3",
  "ANTHROPIC_DEFAULT_OPUS_MODEL": "glm-5.3"
}
```

- 값은 `scripts/glm_slot_gate.py`의 `SLOT_MODEL`과 정확히 일치해야 한다(테스트 `scripts/test_glm_slot_gate.py`가 이 블록을 강제한다). 정책을 바꾸면 게이트·본 블록·역할 표를 함께 바꾼다.
- Z.ai 공식 샘플은 다른 모델명(예: glm-4.x)을 보여 주며 매핑 하드코딩을 권하지 않는다. 본 저장소는 사용자 확정 정책(glm-5.3 계열)을 따르므로 공식 샘플을 그대로 복사하지 않는다.
- **세션 시작 점검**: `python3 scripts/glm_slot_gate.py` — exit 0(PASS) 확인 후 작업한다. exit 1이면 위반 목록의 변수를 채우고 세션을 재시작한다. exit 2는 GLM 세션이 아니라는 뜻이다.
- 매핑 변경은 세션 재시작 뒤에 반영된다고 본다(재시작 전 스폰 결과는 신뢰하지 않는다).

## effort 강등 주의 (본문 §3 실측 인용)

- 카탈로그 미수록 모델(GLM 프록시)에서 xhigh는 high로 자동 강등이 실측됐다 — effort frontmatter는 설정값이며 실발효 값과 다를 수 있다.
- 강등되면 xhigh와 high 계획의 차이는 프롬프트 내용뿐이다. 라우팅의 본질은 effort 수치가 아니라 **역할·산출물 분리** — 강등 시에도 에이전트명(역할) 기준 라우팅을 유지한다.
- 슬롯 실체(sonnet/opus/haiku/fable의 실제 모델)는 프록시 매핑을 따른다 — 슬롯명과 실제 모델의 대응은 연결 설정 문서를 확인한다.

# effort-router — 채팅 앱 paste 카드 (ChatGPT 앱·GLM 앱 공용)

대상: 파일시스템·서브에이전트·스킬 시스템이 없는 채팅 앱 — ChatGPT 앱·GLM 앱(chat.z.ai). 붙여넣기 프롬프트 카드가 유일한 실현 형태다.

- **ChatGPT 앱 지침 계층**: 전 채팅 적용은 Custom Instructions / 프로젝트 단위는 Projects 지침(파일 동봉) / 첫 턴 일회 붙여넣기.
- **GLM 앱**: 지침 기능은 공식 문서 **미확인** — 일회 붙여넣기로 가정한다.

> 본 문서는 effort-router SKILL.md(§1 티어·§3 제약·§6 매핑)의 파생 축약 이식본이다 — 규칙 충돌 시 본문이 우선한다. 본문 갱신 시 본 파일도 파생 갱신한다.

## 붙여넣기 카드

```text
[Effort Router — 단일 세션 축약]
1. 작업 착수 전 티어를 판정해 먼저 출력한다.
   S 단일 파일·텍스트/스타일 / M 2~10파일·~1000줄 이하·위험 없음 /
   L 10파일·1000줄 초과 또는 위험 지표 양성(규모 무관) / XL 코어 엔진·전면 리팩터링.
   지표 충돌 시 상위 티어. 다음 해당 시 1티어 상향: 요청 경로 동작 변경·
   보안 통제 자체 변경·코드만으로 판별 불가 변수(이 경우 확인 질문 1개 먼저).
2. 판정 후 형식 출력: 판정 티어 / 작업 단계 / 적용 에이전트: 해당 없음(단일 세션) /
   팬아웃: 해당 없음 / 단계 상태: 해당 없음 / 실행 지침 요약.
3. 증거 형태: 결론마다 근거를 인용하고, 검증이 필요한 주장은 재질문으로 확인을 요청한다.
4. 역할은 턴 단위로 진행한다 — 첫 턴 "①계획", 다음 턴 "③구현", 그다음 턴 "④리뷰".
```

## 멀티턴 운용 지침 (사용자 운용)

- **①계획 턴**: 계획만 요청한다 — 수정 대상·보존 제약·검증 요구(1줄 검증 가능 형태)를 받고, 구현을 같이 시키지 않는다.
- **③구현 턴**: 직전 계획을 인용시키며 구현만 요청한다.
- **④리뷰 턴**: 계획 대비 구현물 대조를 (주장, 근거, 판정) 형태로 요청한다 — 리뷰가 수정까지 하지 않게 한다.
- **적용 제외**: §2 화이트리스트·팬아웃·state.json(§5) — 앱에는 파일 계약 운반이 없어 역할 시뮬레이션은 턴 대화로 대체한다.
